# Sobermod
This is a mod for the game potioncraft i made durring the summer holliday. The mod is meant to help someone on reddit with alcoholism. 
The game has a wine map, which reminded the user of alcohol every time they see it in the game. They asked for a mod that replaces all references to the wine map with something else. That is what i made.

I already had experience making a mod for this game, so i didn't need to research that. I will be using termanology in this devlog without explaining them, so read my devlog about my first modding project first. I Used AI for large parts of this project to speed up development by writing large blocks of code for me and helping me think through problems. I didn't give AI access to potioncraft source code, i analysed that myself using DotPeek.

I started by copying the starting code from my previous project, so i had a good starting point. I then looked through the de-compiled code to find the potion bases. The code is spread across a large number of classes that all interact to do different things. I found a method that retrieves the title of the base out of the localization system. I was able to hook to that method with a postfix, filter out the __result equal to "Wine" and replace the __result with "Grape juice". This way, when the player hovers their cursor over the wine icon it says "Grape juice" instead. I used the same trick for the description which is displayed under the title, but it's hooking to a different method. When the player clicks on a base they can select which base they want to use. This uses a seperate UI window, which also has it's own button that the player can hover over to make the name of the base apear. Here i was also able to use the same trick.

The localization system of the game uses a dictionary to store the translated text for each language. The first two method that i hooked to use the localization system, and my postfix comes after that. In the third method that i hook to the text is used as a key for the localization system. This means that the localization system is asked to use a key that isn't used in the dictionary, which causes the text to be displayed wrong in some UI elements. To solve that i hooked to a method in LocalizedText, which sets the text in UI elements using the localization dictionary. I added a prefix and filtered the times where the key is equal to "Alkahest" and set the text directly instead of using the localisation dictionary. I have to filter for "Alcahest", not "potion_base_wine", because the third hook already changed the text from "potion_base_wine to "Alcahest".

Customers can sometimes ask for potions made using a specific base. In the textbox communicating to the player what the customer wants the name of the potion base is used. To chnge the text i hook to a method in the QuestRequirement system. This method returns a list of potionbase keys, of which only the first index is used. I added apostfix where i filter using the first index of the list, testing the string and returning a new list with my own list using "Alkahest" as the string. This solved the problem.

I then got in contact with the Redditor who asked for my help. I asked them what they wanted me to replace the text with. I got a reply saying that they want the name "Alkahest", which is a mythological universal solvant. They also wanted me to change sprites to the acid potion sprite. This was a challenge i hadn't done before, but i was up for the challenge.

In the same class i found a method that returns a sprite that gets used as the icon for the wine base selection button. I hooked to that method and added a prefix. In the prefix i test if it's the wine base. there is nothing in the method itself that i can use to identify the call, but i can call a method in the class that calls the method. I decided to call the method that returns the element text. Since i had overwritten that method returning "Alkahest" in place of "potion_base_wine" i had to test for the string "Alkahest" instead. If this returns true i can return a different sprite and prevent the origional method from calling. To get such a sprite i used a GetByName method in the Potioneffect class. This method returns the exact sprite i need and i return that with the postfix. This makes the sprite from the acid potion effect visible as the sprite used by the potion base selection button instead of the wine sprite.

I then did the same trick for the tooltip sprite. Here i did run into a problem though, as the tooltip sprite for wine is quite a bit bigger than the acid icon. This is because the wine icon is decorated with leaves around it. The sprite i needed simply didn't exist in the game. So i decided to make it myself. I could have made the sprite by hand, put it in the files of the mod and loaded it from there, but i wanted to keep the whole mod confined to code alone. I decided to take the sprites from the game and store them in code, so i could modify them in code. Modifying the sprite wasn't easy though, because the sprite itself was flagged unreadable. I asked AI for ideas on how to solve it. It suggested to use Unity's built in graphics system to blit the texture. This means rendering the texture to a rendertexture, and copying the data from the rendertexture onto a new texture that was readable. I needed to do this for the orrigional wine texture and the acid potion effect. To avoid code duplication i put the code in a seperate function. I later put that function into an abstract class called SpriteHelper with a bunch of abstract functions, so i could call these functions from anywhere in my code. To avoid creating the same sprite many times over, i added a static sprite variable to the class associated with the harmony patch for the tooltip sprite postfix. If the postfix is for alkahest i first test if the tooltipsprite has been assigned a value. If it has not been assigned a value i run an algorithm to create the the sprite and assign the sprite to the tooltipsprite variable. If the tooltipsprite variable has been assigned i simply assign the tooltipsprite to the __result.

The algorith to create the sprite changed a bit over time. I started by returning the copied version of the wine sprite, just to test if it works. Then i added a method to the SpriteHelper class called CombineSprites to combine two sprites together by overwriting a part of one sprite with another sprite. This allowed me to copy the acid sprite over the larger wine sprite with the decorations and returning the result. This new sprite had the right size, and had the acid sprite, but the acid sprite was in the top left corned instead of in the center, and there was a large white square replacing a large part of the decoration. I added an offset variable to the method and made it use the alpha channel in the sprite to only overwrite certain parts of the sprite. This looked better, but now you can see the purple blackground and parts of the wine icon, and the scale of the icon wasn't right. To fix the scale i added another method to the SpriteHelper class to scale the acid sprite up or down.

Getting rid of the origional icon and change the background color was a bit harder though. I added a method to the SpriteHelper called RemoveBackground to scan the image, looking for pixels that look like the background, and changing them, for example, making them transparrent. I did this by looping through all the pixels and comparing the color value to the background color. When the difference is less than the tollerance, the RGBA value is set to a new value diffined in the parameters or sampled from the image. I used this to replace the purple with beige, which looked better, but the outline for the wine icon was still there. I then came up with a slightly different approach. I took the small version of the icon, so the version without decoration. I used the RemoveBackground method to make the whole circle purple. I then scaled it down and used the combine sprites method to copy it over the version with the decoration. This removes the outline of the wine icon without removing the purple color. I then use the Remove background method to change the purple color to green. I then use the CombineSprites method to copy the acid sprite over that. This finally created a clean looking result.
