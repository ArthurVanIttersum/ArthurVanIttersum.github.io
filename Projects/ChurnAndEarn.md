# churn and earn project page
This project is part of a Gamejam i did at school.The theme of the gamejam is growth. We decided to make a game about growing a dairy bussiness. For our gamedesign we took inspiration from the famous game cookieclicker. it's a webgame, where you click on cookies to get cookies, and use those cookies to buy upgrades to get more cookies. Since the game itself i will focuss more on the designing work i did for this project.

In our version the player can click on milk to make milk, and click to sell the milk to make money. The player can then use the money to increase the production of milk, but the player still has to click to sell the milk. When the player has made enough money they can upgrade the bussiness, which allows them to make butter, which is 10x as valuable. This creates a big save up leading to a big pay off. The player can then work up to cheese (100x) and then cake (1000x).

Designing the UI was a bit tricky, because we had a lot to display. We decided to go into paint and make sketches of where the buttons and displays should go. After a bit of re-aranging we got to a UI that we we both happy with. We then implemented it into the game using Unity's UI system.

to keep track of the numbers in the game we re-used a script from another course that we were all familiar with. it's a simple scriptable object with an integer and some setter and getter logic. Clicking to make or sell milk was done by connecting the UI button directly to the scriptable object. Making milk over time was done using a simple coroutine with a waitforseconds, where the time between loops approaches 0 the more upgrades you buy. meanwhile the other engineer made a script for buying upgrades, where the cost goes up exponentially.

The artists made assets, such as the buildings, a cow, treasure, and UI Art. We wanted to dedicate one section of the screen to all the buttons, one section to a treasure vault, and one section to the building in a landscape with cows. The artists put their work into prefabs, which we later dragged into the main scene, to avoid merge issues. I added a camera that renders to a render texture, which is displayed in the UI. This allowed us to dedicate a certain area of the screen to a certain area in the scene. I made added a simple script to make the camera rotate and copied this whole system so it works for both the environment and the treasure.

Meanwhile the other engineer added a slider, so the player can sell many items at once. and made a system to spawn and replace scriptable objects based on the amount of treasure and upgrading the bussiness.

At this point we had a playtestable version, so i did some playtesting, to adjust the placeholder numbers we were working with up to that point. I realised that the base speed of resource production should be the same for all of them, because it doesn't feel fun to go from a really fast milk production to a really slow butter production. It should go down to a little slow, which can then be upgraded to go really fast again. I also found that the prices of upgrades were going up too fast. i realized that the code was bugged and i left that problem up to the other engeneer who made that script.

I also discovered that the slider for fast selling, which was added as a quality of life feature, broke the game a bit. It was implemented to sell as many products it could, up to the number selected. There was no reason not to leave products unsold, so the player should leave the slider on 1000 at all times to always sell everything they have in one click. This then reduces the player imput, which was a big sellingpoint of the game. Instead of removing the slider i decided to reworked it into a game mechanic.

In my reworked version you need to have at least the selected number of products to sell that number of products. This means that if you set it to 1000 when you only have 10, nothing will happen. You need to lower the slider down to 5, and then click twice to sell everything. Since the milk and butter are often produced at radically different speeds, the player should move the slider often to sell both products as fast as possible, so they can buy the next upgrade faster. I also changed the numbers on the slider a bit, to spread the out a bit more, but the highest number was still 1000. i didn't want the player to be forced to spam the button to keep up with selling later in the game, and i also didn't want to add an infinite number of buttons. i decided to make the last number 1000+. This means that you need at least 1000 for the botton to work, but when it works it will sell everything you have even if it's more then 1000. This means that there is a one click sell all button, but it's only available when you produce fast enough to to quickly make 1000 and more. At that point the player deserves and needs a one click sell all button.

At the last day we implemented the last art, made a few tweaks, and handed in the project before the deadline. The UI art could not be implemented anymore, because we had connected so much of our code directly to the UI. We were running out of time, so we decided to hand in the latest working version from the artist who hadn't pulled the new UI changes yet.
